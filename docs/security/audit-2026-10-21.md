# Security audit — 2026-10-21

The audit uses `scripts/deps.py` with OSV Scanner 2.7.0 and reviews application
execution boundaries separately from package presence. Six existing lockfiles
and all six initially running images were checked. The analyzer's independent
lockfile is now included. Image scans resolve containers to immutable IDs, save
per-image JSON reports, and return an error if an image cannot be exported.

## Fixes

Backend security floors and lockfiles now include Pillow 13.0.0, fsspec 2026.6.0,
Mako 1.4.2, OpenEXR 3.4.14, aiohttp 3.14.4, anyio 4.14.2, certifi 2026.10.19,
multidict 6.9.1, PyJWT 2.15.0 and urllib3 2.8.0. Analyzer also updates idna and
python-dotenv. Package-specific cutoffs preserve unrelated resolutions. The
new Pillow and compromised-root-CA certifi fixes explicitly bypass the normal
14-day cooloff; other selected versions are aged.

Frontend updates include Vite 6.4.4, Vitest 4.1.11 and compatible fixes for
brace-expansion, browserslist, cookie, devalue, fflate, qs and source-map-js.
Appium's transitive tree is refreshed within declared ranges, with overrides
for the remaining fixable advisories. The basic-ftp, deepmerge-ts and esbuild
branch changes retain the supported Node engines/module interfaces and pass
CLI/API smoke checks.

Local Appium patches address:

- ZIP symlink traversal and duplicate-name arbitrary file writes:
  GHSA-7pqw-9j4j-h8q3 and GHSA-jmr9-qjv8-65gv. Containment checks include existing
  dangling symlinks. Legitimate internal symlinks remain usable.
- Brace parser and AST-walker stack exhaustion: GHSA-vfj7-8cjw-p6xm. Deep inputs
  fail with a controlled 256-level security limit.

Worker format policy (revised after the initial audit builds): BMP is rejected.
Public workers accept JPEG only; trusted auxiliary workers explicitly set
`HILLVIEW_AUX=1` for PNG, GIF, WebP, TIFF, EXR, CR2 and external pyramid input.
These additional paths may need further security audits. The previous
`ALLOW_PANORAMA_FORMATS` variable no longer enables any format.
Both content signatures and suffixes are checked
before decoding, dimension probing, EXIF extraction and RAW conversion, including
EXR/TIFF renamed to JPEG. Public pixel decoding explicitly uses libvips JPEG loading, and dimension
probing restricts Pillow to JPEG. The API stores worker-generated WebP artifacts
without decoding them; this input gate does not change artifact formats.

The custom EXR raster reader was removed. Opted-in internal workers use the
existing libvips native EXR decoder and its `VIPS_DISC_THRESHOLD` disk-spill
behavior. **This restores exposure to the system OpenEXR advisories on opted-in
workers:** only trusted internal inputs belong there. The flag is a format
policy, not a memory budget or an authorization boundary. Existing file/pixel
limits and worker RAM/disk provisioning still apply. Panoramas encoded as JPEG
remain subject to those ordinary size limits.

The 2026-10-22 revision preserves auxiliary decoder behavior: ImageMagick
`identify -ping` and its existing Docker/Compose resource settings are restored,
as are OpenCV pyramid-tile decoding and suffix-based EXR handling. There are
no process-global libvips loader blocks. Public dimensions use JPEG-only Pillow
probing and public pixel loading explicitly uses libvips' JPEG reader. Auxiliary
ImageMagick/native codecs and external tiles still need further security audits;
this policy is not a claim that their vulnerabilities have been resolved.
The worker's subprocess calls use argument arrays; YOLO loads a fixed
operator-supplied model after SHA-256 verification.

## Outstanding upstream/database work

Tauri's GTK stack retains glib 0.18.5; the published fix is in 0.20, which cannot
replace the older GTK dependency's types through a lockfile-only update. Rand
0.7.3 is retained by phf_generator; newer fixed Rand branches do not satisfy that
parent's dependency. fxhash, proc-macro-error, the unic crates, zvariant,
zvariant_derive and zbus_names carry maintenance notices. These need coordinated
parent migrations; incompatible crate overrides were not forced.

The running PostGIS image uses a retired `bullseye-pgdg` apt repository: an
isolated `apt-get update` fails because its Release file is gone. OSV does not
report its PostgreSQL server package, so its scan does not establish that the
server is currently patched. The existing plan is in
`docs/postgres-alpine-migration.md`. Switching libc/database images on the live
volume requires the documented dump/restore and collation procedure, rather
than swapping the image in place. Revalidate the migration target image against
current advisories before executing the older runbook. This audit does not
migrate that database.

## Reproduce and deploy

```
./scripts/deps.py audit --json
./scripts/deps.py images --output-dir /tmp/hillview-image-reports
cd frontend/tests-appium && bun run test:security
```

Rebuild and recreate the relevant services to deploy fixes. Bind-mounted source
does not update installed Python/native libraries. For a deliberate future OS
security refresh, build with `--pull --no-cache` so cached apt/apk layers are not
reused. The legacy Docker builder ignores Dockerfile-specific ignore files; the
frontend audit build uses a temporary source snapshot with those rules applied
as the context's `.dockerignore` and the committed `.env.example` as build
configuration, avoiding private settings and unrelated local build artifacts.

### Narrowed policy revision — 2026-10-22

The decoder replacements are deferred. Auxiliary workers keep the original
ImageMagick probing, native libvips loading (including its existing fallback
selection), EXR suffix dispatch, and OpenCV tile decoding. ImageMagick's memory,
map, disk, width, height, and area build arguments remain wired through Compose.
They do not govern other libraries. The global loader-blocking side effects
have been removed from the input-policy module.

The intentional behavior change is public JPEG-only admission before RAW,
metadata, dimension and pixel parsing, plus rejection of external-pyramid input.
Public pixel loading explicitly selects libvips JPEG; public dimension probing
restricts Pillow to JPEG. Existing orientation/color processing is retained.
The two tests for the deferred Pillow tile decoder have been removed; they
would incorrectly assert protections the restored OpenCV path does not provide.
Earlier test counts and image scan results above are historical, not validation
of this revision. Rebuild and re-audit the worker image before deployment.

Validation of the narrowed revision: 42 format-policy/external-pyramid guard
tests, 8 real-pyramid geometry/stitching tests, and 49 existing photo-processor
and blur tests pass (99 total). Tests include a real auxiliary EXR round trip,
public JPEG dimensions/orientation, rejection of disguised non-JPEG inputs,
absence of global loader mutations, and the auxiliary identify command/timeout.
The worker Docker image was not rebuilt in this revision.
